# データ系機能 仕様書（SEOディレクションOS・データ層）

> ステータス: 仕様確定（2026-08-12・Day 6 壁打ち）。実装は v1 公開後にロードマップ順で行う。

## 1. 位置づけ

seo-grit は「新規記事の作成ツール」（v1）から、**SEOメディア運営のディレクションOS**へ拡張する。

ディレクションOSとは：GSC・GA4・WordPress のデータを1か所に収束させ、
「今日は何をやるべきか」——リライト／タイトル改善／内部リンク／新規記事／統合／削除／CV改善／技術修正——の
優先順位を、根拠の数値と見込み効果つきで提示し、施策の実行から効果検証までを台帳で管理するもの。

リライト機能はこのOSの一部（処方箋の1種）であり、独立した機能ではない。

## 2. 設計原則

1. **公開後の記事はWordPressが正本**。データ層は観測・判断のための蓄積であり、コンテンツの複製管理はしない
2. **蓄積型**。すべての取得はスナップショットとして日付つきで保存する。APIの保持期間（GSC 16ヶ月等）に
   依存せず、リライト前後の比較・長期トレンドを自前のデータで行う
3. **ファイル＝データベース（JSON）**。スキーマを安定させ、将来の管理画面（サーバー型Webアプリを想定。
   ヒートマップ等の高度な可視化に耐える形）は、このデータ層を読むだけで載るようにする。
   データと画面を最初から分離しておく
4. **収集は決定論スクリプト、分析はClaude**。診断ルール・処方箋・効果試算の計算式はスキルに明文化し、
   本人との対話で改善し続けられるようにする（ブラックボックス化させない）
5. **外部連携の初期設定はすべて「伴走セットアップ」**。GCPのサービスアカウント作成も、GA4のキーイベント
   設定も、非エンジニアがClaudeに付き添われて完了できる形で製品に組み込む。自環境でもクライアント環境でも
   同じ手順で毎回伴走する

## 3. データソースと認証

| ソース | 取るもの | 認証 | 料金 |
|---|---|---|---|
| WordPress REST API | 記事マスタ・本文（解析用） | 既存の `.env`（アプリケーションパスワード） | 無料 |
| Search Console API | 検索パフォーマンス・インデックス状況・サイトマップ | サービスアカウント（下記） | 無料 |
| GA4 Data API | 行動データ・キーイベント（CV） | 同じサービスアカウント | 無料 |
| 外部キーワードAPI | 検索ボリューム等（フェーズ3） | 各サービス | 有料が主 |

**サービスアカウントは1個で GSC・GA4 を兼用**する。伴走セットアップの内容：
GCPプロジェクト作成 → 2つのAPI有効化 → サービスアカウント作成・鍵JSON発行 →
GSCプロパティとGA4プロパティにそのメールアドレスを閲覧者として招待 → 鍵のパスを `.env` に記載。
課金の有効化（クレジットカード登録）は不要。

## 4. データ構成（作業フォルダの `data/` 配下・7カテゴリ）

```
data/
  articles/
    articles.json        … ① 記事マスタ＋本文解析（コンテンツ資産）
  gsc/
    performance/<日付>.json … ② 検索需要・順位
    index/<日付>.json       … ③ インデックス・技術SEO
  ga4/
    <日付>.json             … ④ ユーザー行動・CV
  site/
    internal-links.json  … ⑤ 内部リンクグラフ（①から導出）
  topics/
    topics.json          … ⑥ トピッククラスター構造（対話で育てる）
  keywords/
    opportunities.json   … ⑦ 新規記事の機会
  actions/
    actions.json         … ⑧ 施策・ディレクション履歴（PDCA台帳）
  reports/
    monthly/             … 月次レポート出力先
```

### ① articles/articles.json（記事マスタ＋解析）

WPから取得：ID／slug／URL／タイトル／meta description／公開日／更新日／ステータス／
カテゴリ／タグ／著者／アイキャッチ有無／canonical／noindex有無。

本文をローカル解析して導出（APIではなくパースで得る）：
文字数／見出し構造（H2/H3ツリー）／内部リンク（リンク先記事IDの一覧）／外部リンク数／
画像数／構造化データの有無。

これにより追加インフラなしで導出できるもの：カニバリゼーション候補（同一クエリ・類似見出しの突合）／
重複タイトル・重複description／orphanページ（内部リンク入次数ゼロ）／内部リンク提案。

### ② gsc/performance/（検索需要・順位）

行の軸：**記事URL × クエリ × 日付 × デバイス**。
指標：clicks／impressions／ctr／position。
country・search appearance はスキーマ上オプション（国内メディアの既定では取得しない）。
取得期間：初回はAPIの遡及可能な全期間、以降は前回取得日からの差分。

### ③ gsc/index/（インデックス・技術SEO）

URL Inspection API による記事ごとの：インデックス登録状況／最終クロール日時／Google選択のcanonical／
robots判定。＋ Sitemaps API によるサイトマップの送信状態・自動再送信。
broken link・自前クロールによる網羅的な技術診断はフェーズ3（それまでは①の導出で代替）。

### ④ ga4/（ユーザー行動・CV）

記事URLごと：sessions／users／新規ユーザー／**平均エンゲージメント時間**／エンゲージメント率／
直帰率／スクロール90%到達数／ランディング・離脱／流入元（source / medium / campaign）／デバイス。

**キーイベント（CV）**：LINE登録・問い合わせ・CTAクリック等、`keyEvents: {イベント名: 件数}` の形で保持。
GA4側でキーイベントが未設定の間は null（欄は初日から存在させる）。設定自体を伴走タスクとして製品化し、
設定完了をもって**「SEO順位ベース」から「売上ベース」の優先順位づけが解禁**される。

### ⑤ site/internal-links.json（内部リンクグラフ）

①の解析結果から生成する隣接リスト（記事ID → リンク先記事IDs）。
入次数・出次数、ピラー↔クラスター間のリンク欠落の検出に使う。

### ⑥ topics/topics.json（トピッククラスター構造）

**APIから取れない、編集判断のデータ**。knowledge.md と既存記事を材料に、Claudeと本人の対話で初期生成し、
記事を作るたびに育てる。

トピックごと：ピラー記事／クラスター記事（既存）／未作成キーワード。
記事ごと：topic／親topic／primary keyword／secondary keywords／検索意図／ファネル段階／想定ペルソナ／
pillar・cluster区分／関連記事。

これがあると「リライトより新規記事を書くべき」「この記事とこの記事を統合すべき」という
**記事単体を超えたディレクション判断**が可能になる。

### ⑦ keywords/opportunities.json（新規記事の機会）

キーワード／想定検索意図／検索ボリューム／自サイトの現在順位／既存記事の有無／関連トピック／
優先度／CV期待値。

第1段階（GSCのみ・無料）：「表示されているのに対応記事が無いクエリ」「既存記事が21位以下で
沈んでいるクエリ」を②から抽出して登録する。
第2段階（フェーズ3）：外部キーワードAPIで検索ボリュームと未露出キーワードを補完する。

### ⑧ actions/actions.json（施策・ディレクション履歴＝PDCA台帳）

1施策1レコード：日付／対象記事／施策種別（リライト・タイトル改善・内部リンク・新規作成・統合・削除・
CV改善・技術修正）／変更内容の要約／**仮説（なぜ効くと考えたか）**／Before数値（順位・表示・CTR・
エンゲージ）／**測定予定日**（実施4〜8週後）／After数値／成否判定と学び。

このファイルが「台帳駆動の声かけ」の源泉になる：セッション開始時に測定予定日・次回診断推奨日を
チェックし、期日が来ていたらClaudeから切り出す。蓄積されると**ディレクションの打率**が可視化され、
診断ルール自体の改善材料になる。

## 5. 診断エンジン（ルールはスキルに明文化）

データ層の上で、以下の確定済みルールにより記事ごとの処方箋を出す：

- **順位帯ルール**：4〜10位=最優先／11〜20位=主力／21〜50位=構成見直し／51位以下=書き直し・統合・放置判断
- **表示×CTRマトリクス**：表示多×CTR低（順位比）→タイトル・meta改善／表示多×順位低→本文強化／
  CTR高×順位低→内容のE-E-A-T補強／表示少×順位高→対象外
- **GA4軸**：順位・CTR正常なのに平均エンゲージメント時間が短い→リード文・冒頭のリライト
  （スクロール到達で裏取り）
- **時間ルール**：公開90日未満は「熟成中」で対象外（タイトル・metaのみ60日で解禁）／
  リライト後4〜8週は再リライト禁止（効果測定期間）／表示回数が月100未満は「データ不足・判断保留」
- **トピック軸**（⑥導入後）：クラスター欠落→新規記事提案／カニバリ→統合・棲み分け提案
- **効果試算**：順位別CTRカーブによる見込みクリック増（幅つきで提示）。CV接続後は見込みCV増・売上ベース

処方箋は8種：リライト／タイトル改善／内部リンク／新規記事／統合／削除／CV改善／技術修正。

## 6. 運用サイクル

- **都度起動**（「ディレクションして」）＋**台帳駆動の声かけ**（期日が来たらClaudeから切り出す）を基本形とする
- 定期自動実行（週次診断）は、診断精度が実データで検証できてから載せる
- 可視化：当面は診断のたびにレポートを生成。**管理画面はサーバー型Webアプリを将来実装**する前提で、
  データ層はその読み取り元となるようスキーマを安定させておく（本仕様の原則3）
